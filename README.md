# DHT Algorithm Lab

**DHT Algorithm Lab** — интерактивная учебная лаборатория для изучения и сравнения алгоритмов распределённых хеш-таблиц **Chord** и **Kademlia**.

Приложение визуализирует поиск по шагам: в Chord — переходы между узлами кольца, в Kademlia — раунды запросов `FIND_NODE` к нескольким контактам.

Алгоритмы и расчёты выполняются на **Go**, а браузер показывает результаты через **HTML, CSS, JavaScript и SVG**.

## Возможности

- Выбор алгоритма **Chord** или **Kademlia**.
- Настраиваемая битность идентификаторов: **от 1 до 16 бит**.
- Ручной ввод ID узлов или генерация случайной сети (до **100 уникальных узлов**, но не больше размера ID-пространства).
- Выбор начального узла и целевого ID.
- Пошаговый просмотр с кнопками **«Начать»**, **«Следующий шаг»**, **«Назад»** и **«Сброс»**.
- **Chord:** визуализация кольца, маршрута, владельца ключа и Finger Table текущего узла.
- **Kademlia:** отображение XOR-расстояний, k-buckets, опрошенных контактов и их ответов. Один шаг визуализации соответствует **целому раунду**, содержащему до `α` запросов.
- Настраиваемые параметры Kademlia: **`k`** (ёмкость k-bucket) и **`α`** (число запросов за раунд).
- Метрики: количество переходов Chord, запросов и логических раундов Kademlia.

## Технологии

- **Backend:** Go, `net/http`, `encoding/json`.
- **Frontend:** HTML, CSS, JavaScript без фреймворков.
- **Визуализация:** SVG.
- **Хранение:** всё в оперативной памяти; база данных не требуется.

## Запуск

Понадобятся **Go 1.22+** и современный браузер.

```bash
git clone https://github.com/Gubarenko-Vladislav/dht-lab.git
cd dht-lab
go run ./cmd/server
```

Открой в браузере **http://localhost:8080**.

Проверка сервера: **http://localhost:8080/health**.

> Запускай команду из корня проекта: сервер раздаёт файлы из каталога `web/`.

## Как пользоваться

1. Выбери **битность ID** и **количество узлов**, затем нажми **«Случайная сеть»**. Вместо генерации можно указать ID вручную и нажать **«Создать сеть»**.
2. Выбери алгоритм **Chord** или **Kademlia**.
3. Укажи **начальный узел** (его ID должен присутствовать в сети) и **целевой ID**.
4. Для Kademlia задай `k` и `α` (`1 ≤ α ≤ k`).
5. Нажми **«Начать»**, затем переключай шаги кнопками **«Следующий шаг»** и **«Назад»**.


## Особенности и ограничения

Проект предназначен для **изучения алгоритмов**, а не для развёртывания настоящей P2P-сети.

- Узлы виртуальные; между ними нет реальных сетевых соединений или RPC.
- В Kademlia параллелизм `α` **моделируется логическими раундами**: запросы одного раунда выбираются вместе, а ответы объединяются после завершения раунда. Это не реальные одновременно работающие goroutines.
- k-buckets создаются при построении статической сети. Полноценное обнаружение узлов, обновление контактов и хранение значений (`STORE`/`FIND_VALUE`) не реализованы.
- Kademlia возвращает **ближайшие узлы по XOR**, а Chord — **узел, ответственный за ID ключа**. Эти результаты имеют разный смысл.
- Состояние сети и результаты поиска не сохраняются между перезапусками приложения.

## Цель проекта

Наглядно показать, чем отличаются маршрутизация по **Finger Table** в Chord и итеративный поиск по **XOR-расстоянию и k-buckets** в Kademlia, а также как параметры сети влияют на процесс поиска.
